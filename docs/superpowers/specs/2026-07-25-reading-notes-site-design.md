# 文獻筆記站（bkwmt.github.io）設計文件

日期：2026-07-25
狀態：使用者已核可設計對話，待審本文件

## 1. 目標與定位

把 Crossley 精讀筆記（現有三份導讀）發布成公開網頁，讓使用者在外（含手機）也能閱讀，並提供交叉比對與互動功能。網站定位為**文獻筆記站**：首頁是各輯系列的總入口，Crossley 精讀是第一輯；之後新增其他文獻（Hennion 等）只加新輯、不改架構。

**最高原則：完全根據文本。** 所有網頁內容逐字取自 `research_library/Nick Crossley/notes/*.md`（唯一權威資料源）。交叉比對只做「選取與並排」，不改寫、不添述；每則引文附原書頁碼。

## 2. 技術路線

- **Astro** 靜態產生器（使用者選定），content collections 管理導讀 markdown。
- 互動元件用 vanilla JS（Astro islands 模式），無後端、無框架 runtime。
- 部署：GitHub Actions 官方 Astro workflow，push main → 自動 build → GitHub Pages。
- 本機 repo：`~/Developer/bkwmt.github.io`，並在 `Developer/CLAUDE.md` 登記。

## 3. 資訊架構

```text
/                        首頁：筆記站入口，系列卡片（目前一輯）
/crossley/               第一輯首頁：閱讀地圖（出版譜系 2008 期刊文 →
                         2015 專書 → 2015 論文集；三份已完成、三項排隊中）
/crossley/notes/<slug>   導讀全文 ×3（markdown 渲染）
/crossley/concepts       概念索引（可搜尋篩選）
/crossley/themes         跨文本主題對照
/crossley/quotes         關鍵句引文庫
```

閱讀狀態（已完成／排隊中）直接呈現在 `/crossley/` 首頁，不做獨立互動頁。

## 4. 資料流

### 4.1 同步（唯一權威資料源）

`notes/*.md` 永遠是權威。repo 內 `scripts/sync-notes.sh` 把導讀複製到 `src/content/notes/` 並注入 frontmatter（標題、出處、年份、slug）。日後新導讀（如 SNMW Ch11）寫完：跑 sync → git push → 自動部署。

### 4.2 機械解析（build 時，零人工）

依導讀既有的標題慣例解析：

- **關鍵句引文**：解析標題含「關鍵句」字樣的區塊下的清單 → 引文庫資料。實際標題有變體，解析器都要認：Ch1 為 `### 關鍵句（seminar 可引）`／`### 關鍵句`，Ch2 為 `## 五、seminar 關鍵句選`。**2008 篇（Pretty Connected）沒有專門關鍵句區塊**（只有「理論骨架一覽」），引文庫初版不含該篇；若要納入，需在導讀中補一節關鍵句（動到權威文本，由使用者決定，不在本版範圍）。
- **概念清單**：Ch2 導讀「全章技術概念清單（63 項）」的結構化列表 → 概念索引基礎資料。

此慣例即 schema：日後導讀維持同樣標題慣例（建議統一用 `### 關鍵句`），互動頁自動長出新內容。

### 4.3 人工編纂（可審的資料檔）

- **`src/data/themes.yaml`**（主題對照）：唯一需要編輯判斷的部分。主題初稿：punk 網絡案例、music worlds vs 次文化、社會資本、對 Bourdieu 的態度。每條目為「文本、段落 anchor、原書頁碼、逐字摘錄自導讀」。選取與並排是編輯行為，但每一個字都出自導讀；此檔供使用者直接審。
- **`src/data/concepts.yaml`**（概念跨篇對映）：補充「概念 → 其他篇出現位置的段落 anchor」，不添加任何新解釋。

## 5. 互動元件

全部 client-side、無後端：

1. **概念索引** `/crossley/concepts`：搜尋框即時過濾（中英文皆可搜，概念保留原文）＋分類 chips（沿用 Ch2 清單既有分組）。概念卡片展開顯示：導讀中的定義段落（逐字）、原書頁碼、連回導讀全文該節。
2. **主題對照** `/crossley/themes`：左側主題清單，右側依文本分欄並排（2008 期刊文｜SNMW Ch1｜Ch2），每欄為逐字摘錄＋頁碼＋回導讀上下文連結。行動裝置退化為垂直堆疊。
3. **引文庫** `/crossley/quotes`：卡片流，依文本篩選；複製按鈕自動帶出處與頁碼。
4. **導讀全文頁**：右側浮動目次（scroll-spy 高亮當前節），頁碼標記保留在標題中；行動裝置目次收合為底部按鈕。

## 6. 註記功能（localStorage＋匯出）

- **記註**：導讀全文頁選取文字 → 浮出「註記」鈕 → 面板選類型（勘誤／提問）＋寫內容 → 存 localStorage。已註記文字重訪時淡色高亮。
- **錨定**：存「頁面 slug＋所在小節標題＋選取原文＋前後各約 30 字上下文」。以文字內容錨定（W3C Web Annotation 的 text quote anchoring 思路），導讀修訂重排後仍可重新定位；找不到錨點的註記列為「待對位」，不消失。
- **匯出**：「我的註記」面板（每頁右下角進入）列出全部註記與則數，一鍵匯出 Markdown 或複製剪貼簿。每則含：頁面、小節、選取原文、類型、註記內容、時間戳——語言模型不需看網站即可在 `notes/*.md` 定位處理。
- **限制（已知並接受）**：localStorage 綁單一裝置瀏覽器；手機記的需在手機上匯出傳回。清除瀏覽器資料前須先匯出（面板顯示則數提醒）。

匯出格式範例：

```markdown
## 註記 3（勘誤）
- 頁面：2015_SNMW-Ch2_What-is-SNA_導讀
- 小節：（三）Levels of analysis
- 選取原文：「⋯⋯betweenness 測量的是⋯⋯」
- 註記：這裡的翻譯應該是「中介中心性」不是「介數」
- 時間：2026-07-26 14:32
```

## 7. 視覺方向

閱讀優先的學術筆記風：內文行寬約 38em；標題明體系襯線、內文黑體；淺深雙主題（跟隨系統）；引文卡片細邊框＋充足留白；不做花俏動效。實作時以 frontend-design skill 細化。

## 8. 錯誤處理與邊界

- sync script 遇到不符標題慣例的導讀：build 不失敗，該篇跳過機械解析並在 build log 警告（導讀全文仍正常發布）。
- themes.yaml / concepts.yaml 引用的 anchor 失效：build 時檢查並警告，頁面上該條目顯示「來源段落待對位」而非壞連結。
- 註記錨點失效：列入「待對位」清單，匯出時保留完整內容。

## 9. 測試

- sync script 與解析器（關鍵句、概念清單）以現有三份導讀為 fixture 寫單元測試。
- anchor 檢查納入 build（astro build 前置步驟）。
- 互動元件以 Playwright 做基本煙霧測試（搜尋過濾、註記存取與匯出）。

## 10. 已知取捨與提醒

- 導讀含 Crossley 原文英文短引文：附完整出處＋頁碼，屬學術合理使用慣例；整站公開，導讀完整譯述也隨之公開。若日後在意，另議存取限制，本版照公開做。
- 註記選 localStorage 而非 GitHub Issues（使用者選定）：換取零跳轉與私密性，代價是跨裝置需手動匯出。
- 未納入本版：出版譜系互動時間軸（使用者未選）、個人簡介頁。
